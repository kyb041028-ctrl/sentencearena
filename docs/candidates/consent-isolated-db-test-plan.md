# 성향 삭제 후보 — 격리 DB 실행 준비

작성일: 2026-10-19
현재 승인: 운영 데이터와 분리된 시험용 DB 검증.
현재 상태: 기존 실행 환경을 찾지 못해 실제 SQL 검증 미착수. 기존 241개 오프라인 검사를 실제 DB 검증으로 재분류하지 않는다.

## 읽기 전용 확인 결과

- PATH와 일반 설치 경로에서 PostgreSQL의 postgres·initdb·pg_ctl·psql, Docker 실행 환경을 찾지 못했다.
- 저장소 기본 `.env`에서 DEV/TEST 전용 DB 설정 이름을 찾지 못했다. 일반 DB 설정의 값은 보고서에 출력하지 않았으며 해당 주소로 접속하지 않았다.
- 시험용 DB라고 확정할 수 없는 기존 연결을 재사용하지 않는다. 별도 DB 서버를 아직 시작하지 않았다.

## 추가 승인 후 실행할 구체적 범위

1. PostgreSQL 공식 Windows 다운로드 페이지가 안내하는 배포처의 지원 중인 안정 버전 바이너리 ZIP을 다운로드한다. 프리릴리스는 선택하지 않는다. 다운로드 출처·버전·실행 파일 서명을 확인한다.
2. 고유한 로컬 임시 디렉터리 아래 도구와 데이터 폴더를 분리한다. 기존 프로그램 설치 폴더, PATH, Windows 서비스·자동실행·방화벽·프로젝트 `.env`는 변경하지 않는다. 환경변수는 시험 프로세스에만 한정한다.
3. 별도 PostgreSQL 클러스터를 초기화하고 127.0.0.1 전용의 비어 있는 높은 포트에서 잠시 실행한다. 인증은 임시 비밀번호와 SCRAM을 사용하고, 값은 채팅이나 테스트 로그에 출력하지 않는다. 운영 자격증명·회원 데이터를 복사하지 않는다.
4. 이 클러스터에만 시험 DB와 가짜 auth·회원·게시글·반응·성향 기록을 만든다. 대상 DB명·localhost 주소·고유 실행 식별자를 모두 검증한 뒤 fixture와 후보 SQL을 적용한다. 운영용 주소 입력은 거부한다.
5. SQL 문법·권한, 철회 성공·부분 오류 롤백·재시도, 과거/취소 반응 사본 정리, 다른 회원 정보 보존, 집계 유지, 외계 moderation 보존, 탈퇴, 동시 철회·반응·예약 계산·재동의·공개 설정 경쟁을 검사한다.
6. 발견한 문제는 기존 승인 범위의 별도 코드 후보에서 수정하고 다시 검증한다. 변경 범위를 자동 확대하지 않는다. DB 검증 결과와 약관 후보 설명을 정리한다.
7. 이번에 만든 시험 DB 프로세스만 종료한다. 다른 서버를 종료하지 않는다. 임시 비밀번호는 폐기하고, 시험용 자료·다운로드 정리 시 절대 경로가 이 작업 전용 폴더 안인지 확인한다. 검증 결과는 secret 없이 후보 문서에 남긴다.

## 영향·복구·비용

- 영향: 로컬 디스크 사용, 다운로드, 시험 중 CPU·메모리 사용 및 localhost 포트 점유. 운영 DB·NAVER 서버·외부 서비스 상태에는 변경 없음.
- 복구: 이번 시험 프로세스 종료 후 새로 만든 작업 전용 폴더를 제거하면 된다. 시스템 서비스 설치와 전역 설정 변경을 하지 않는다. 삭제 대상은 가짜 데이터뿐이며 실제 회원 정보를 가져오지 않는다.
- 비용: PostgreSQL 도구와 로컬 검증에 별도 서비스 사용료·cloud 자원 비용을 발생시키지 않는 계획이다. 다운로드 및 일반 PC 사용은 기존 이용 환경 범위다. 유료 도구나 새 cloud 자원이 필요해지면 실행하지 않고 별도 승인받는다.
- 미승인: 새 도구 준비(설치에 해당), 시험 DB 프로세스의 시작·종료는 각 실행 범위를 위와 같이 명시하여 추가 승인받기 전 수행하지 않는다. 기존 승인으로 운영 migration·배포·commit·push·master 반영은 허용되지 않는다.
