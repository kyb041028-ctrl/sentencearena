# 3차 정합성 후보 기록

상태: 코드 후보와 오프라인 검사. 운영 검증 완료가 아니다. 이 폴더는 공식 기준본이 아니다.

이 기록은 3차 폴더에만 있다. master 문서, STATE, DECISIONS는 고치지 않았다. SQL을 DB에 적용하지 않았다.

## 동의 철회

2차에서 복사된 서버 변경은 유지한다. 성향 상태, 성향 이력, 영토 이력 삭제가 오류를 돌려주면 동의 행을 비우기 전에 실패한다. 이것은 트랜잭션이 아니다.

부분 해결: 삭제 함수가 던지지 않고 오류 객체를 돌려주는 거짓 성공.

미해결: 앞 표만 지워진 부분 삭제, 동의 행 갱신 실패, 동시 반응과 재동의, 반응 사본, 프로필 개척·수호, Daily Issue와 백업, 서버 실패 뒤 브라우저 저장.

정책으로 정하지 않은 것: 개척·수호를 중앙으로 되돌릴지, 반응 점수 사본을 비울지. 외계 소속은 철회로 바꾸지 않는다.

별도 실험 sentencearena-agent-political-consent의 서버 JS는 넣지 않았다. 그 JS만 올리면 없는 RPC 때문에 연령 확인, 동의 저장, 철회, 공개 설정이 실패한다. 3차 서버의 연령 확인과 동의 저장은 계속 표에 직접 쓴다.

2026-10-20 격리 PostgreSQL 53개 검사는 그 실험 SQL의 과거 기록이다. 이 세션에서 다시 실행하지 않았다. 운영 검증 완료가 아니다.

그 53개가 당시 최소 스키마에서 본 것: 철회 후 성향 표 정리, 반응 사본 NULL, 외계 소속 유지, 개척·수호를 중앙으로, 반복 철회, 실패 시 롤백, 롤백 후 재시도, 재동의 뒤 옛 계산 생략, 시험한 동시 철회와 반응, 탈퇴 대기 중 재동의 차단.

그 53개가 빠뜨린 것: 모든 잠금 순서와 교착, 모든 반응·영토·트리거 조합, Daily Issue와 선택 표, 전체 Supabase 인증과 RLS, 브라우저와 API, 운영 함수 본문 전체 대조, 운영 데이터 양.

## 탈퇴와 권한

감사 SET NULL SQL과 service_role GRANT SQL은 검토만 했다. 적용하지 않았다.

GRANT 추가는 최소 권한 완성이 아니다. 기존에 넓게 준 권한을 거두지 않는다.

합법적으로 남는 기록: 감사 행의 행동·이유·대상·메모·시각, legal_hold 보존, 신고 기록, 제재 기록, 글과 댓글 본문, 탈퇴 감사의 건수.

남는 식별자: 운영에 SET NULL이 적용되기 전 감사 행의 회원 번호, 반응에 복사된 점수와 영토, 프로필 영토, 브라우저 저장. SET NULL 이후에도 이미 비운 번호는 트리거를 되돌려 복구되지 않는다.

STATE는 계정 탈퇴와 2026-09-06 legal_hold를 완료로 적고, 2026-10-25에는 감사 SET NULL이 개발 DB에만 있어 운영에서 감사 이력이 있는 탈퇴가 실패할 수 있다고 적는다. 코드를 본 결과 그 긴장과 같다. STATE는 고치지 않았다.

## 신고와 제재

board-service의 처리 순서는 신고 상태를 먼저 바꾸고, 제재 훅, 숨김, 감사 추가, 그 다음 알림이다. 감사 추가 실패는 SANCTION_AUDIT_ATOMICITY_LIMITATION 또는 REPORT_REJECT_AUDIT_ATOMICITY_LIMITATION으로 남고, 알림은 그 뒤에도 시도한다. 같은 상태의 재처리는 거절 감사를 다시 넣지 않는다. 알림은 이전 상태가 이미 종료면 건너뛰고, 같은 dedupeKey는 중복으로 센다.

이 순서를 서버에 다시 연결하지 않았다. 끝난 사건을 다시 실행하거나 알림을 또 보내면 DEC-016 알림이 빠지거나 중복될 수 있다.

대신 docs/candidates/report-audit-compensation.candidate.js가 계획만 만든다. 끝난 사건만 본다. 제재 재적용, 상태 변경, 다시 숨김은 항상 하지 않는다. 성공한 감사가 없을 때만 한 종류를 넣는다. 알림은 기록이 없다고 명시된 때만 보낸다. 이 파일은 서버가 require하지 않는다.

## 게시판 DB 보호

sentencearena-agent-board-db-guards는 d62bab5 기준 SQL 후보다. GitHub master 72573ac의 서버 게시판 파일과 반응 SQL 경로는 그 기준 이후 두 마이그레이션 추가로만 달라졌다. 가드 SQL은 이 폴더에 복사하지 않았다.

넣지 않은 이유: 반응 함수 본문 해시를 옛 기준에 고정한다. 글쓰기 조건에 성향 동의와 영토 공개 동의를 묶는다. 폐기된 KANTAPBIYA_RESIDENT를 본다. 영토를 개척·중앙·수호만 허용해 외계 영토 키와 어긋난다. 이 중 하나라도 넣으면 동작 중인 가입·쓰기·영토 기준이 바뀐다. 넓은 스키마는 승인 전 항목으로 남긴다.

그 실험의 오프라인 검사와 개발 DB 기록은 이 세션에서 다시 실행하지 않았다. 개발 DB 스크립트는 격리 증명이 아니다.
