# 개인정보·운영 증거 보관 검토안

작성일: 2026-10-19
상태: 내부 검토 후보. 기존 정책을 대체하거나 보관을 연장하는 확정 문서가 아니다.
범위: 로컬 코드·SSOT·공개 법령 대조. 실제 회원 자료, DB, 운영 서버는 조회·변경하지 않았다.

## 목적과 판정 기준

운영자와 이용자를 보호하는 데 필요한 증거를 빠짐없이 관리하되, 관계없는 개인정보까지 모으지 않는다. 기록마다 목적·최소 항목·보관 시작점·파기 조건·법적 근거를 구분한다. 기존 코드에 기간이 있어도 적법성이 자동 인정되는 것은 아니다.

개인정보 보호법 제15조·제16조는 적법한 처리 근거와 최소 수집을 요구하며, 제21조는 불필요해진 정보의 지체 없는 파기를 원칙으로 한다. 정당한 이익을 근거로 삼으려면 필요성·관련성·합리적인 범위 및 정보주체 권리와의 비교를 구체적으로 입증해야 한다. 단순히 약관에 적거나 장차 분쟁이 있을 수 있다는 이유로 일괄 보관하지 않는다. 민감정보에는 제23조의 별도 요건도 적용된다.

아래 '최소 항목 후보'는 필요한 범위에 대한 검토안이다. 현재 저장 필드를 전부 적법하다고 승인한 목록이 아니며, 필드 추가·삭제를 실행한 것도 아니다.

## 1. 계정·프로필

- 목적: 계약 유지 중 회원 식별과 서비스 제공.
- 최소 항목 후보: 회원 식별번호, 활동명, 계정 상태, 필요한 가입·연령 확인 기록. 소셜 로그인 인증정보의 실제 수신 항목은 별도 확인한다.
- 현재: 탈퇴와 동의 철회가 다른 절차다. 철회만 하면 계정은 남으며 참여 기능은 제한된다.
- 삭제: 탈퇴 시 불필요해진 정보는 지체 없이 파기하고, 별도 근거가 있는 운영 증거만 분리하여 처리한다.
- 미결: 철회 후 남는 계정 정보의 필요 범위와 유지 기간·종료 절차. 계정 전체를 임의로 1년 보관하는 기준은 만들지 않는다. 제한만 해 두고 무기한 보관하는 방식도 확정하지 않는다.
- 근거 확인: 계약 이행에 필요한 범위와 동의에 의존하는 범위를 구분해야 한다. 재동의 가능성이 있다는 이유만으로 전체 정보 보관이 정당화되지는 않는다.

## 2. 정치성향 점수·변화·영토 이동 기록

- 목적: 동의한 회원에게 성향 분석·영토 기능 제공.
- 최소 항목 후보: 실제 계산에 필요한 반응 및 점수·변화·이동 정보. 추가 수집은 승인하지 않는다.
- 현재: 동의 철회 함수는 성향 상태·변화 이력·영토 이동 이력을 삭제하고 관련 동의 시각을 비우도록 작성되어 있다.
- 삭제: 동의 철회 또는 탈퇴 때 원칙적으로 파기한다. 별도 적법한 근거와 민감정보 요건 확인 없이 분쟁 대비 명목으로 계속 보관하지 않는다.
- 미결: 세 테이블 삭제 외 반응 시점 스냅샷·복제 자료·백업 등에도 대상 정보가 남는지 확인해야 한다. 삭제 함수 일부는 DB 오류 반환값을 확인하지 않아 삭제 성공을 보장하지 못한다. 코드 수정·실제 삭제 검증은 이번 작업에서 수행하지 않았다.
- 근거 확인: 제23조 및 제37조. 일반 개인정보의 정당한 이익 근거만으로 민감정보 처리를 정당화하지 않는다.

## 3. 회원이 삭제한 글·댓글 증거

- 목적: 구체적인 분쟁·권리침해 및 부정이용 확인.
- 현재 코드상 항목: 원문·제목, 원래 콘텐츠 식별번호, 작성·삭제 시각, 삭제 사유, 작성자 식별번호·표시명, 보관 만료일·보전 상태.
- 최소 항목 후보: 사건 대상을 구분할 번호, 필요한 증거 본문·시각·사유. 작성자 표시명·전체 본문 보관의 필요성과 개인정보 노출을 별도로 검토한다.
- 현재 기간: 삭제일부터 6개월. 일반 탈퇴일부터 6개월이라는 뜻이 아니다.
- 삭제: 만료 후 통제된 파기 경로. 개별 사건의 적법한 증거 보전이 필요한 경우만 예외를 검토한다.
- 근거 확인: 6개월은 운영 기준이며 일률적 법정 의무기간이 아니다. 모든 삭제 콘텐츠를 일괄 보관하는 필요성과 정당성을 입증해야 한다.
- 주의: 성향 점수 필드를 제외하더라도 글의 본문 자체에 정치적 견해·타인의 개인정보가 있을 수 있다. 필드 제외만으로 민감정보 문제가 해결됐다고 보지 않는다.

## 4. 일반 신고·처리 기록

- 목적: 신고 검토, 판단 근거 확인, 이의·분쟁 대응.
- 최소 항목 후보: 신고 식별번호, 대상 콘텐츠, 필요한 관계자 식별값, 신고 사유·소명, 접수·처리 시각, 결과와 필요한 증거 연결.
- 현재 기간: 최종 처리일부터 1년.
- 미결: 미처리 건은 최종 처리일이 없으므로 실제 종료·정리 관리가 필요하다. 신고자의 연락처와 무관한 활동내역을 추가로 보관하지 않는다.
- 삭제: 만료 후 파기. 탈퇴나 재로그인으로 기존 기간을 새로 시작하지 않는다.
- 근거 확인: 운영 기준 1년의 필요성 및 적법한 처리 근거 검토가 남아 있다. 신고문에 포함된 민감정보·제3자 정보도 검토한다.

## 5. 제재·이의제기 기록

- 목적: 제한 집행, 운영 판단과 이의제기 검토, 제재 회피 대응.
- 최소 항목 후보: 필요한 회원 식별값, 제재 종류·사유·시작·종료일, 판단 근거 및 이의 처리 결과. 성향 점수는 제재 근거가 아니다.
- 현재 기간: 종료일이 있는 제재는 제재 종료일부터 1년.
- 미결: 현재 기록 생성 함수는 영구정지 또는 종료일 없는 경우 만료일을 비울 수 있다. '모든 제재 기록은 1년 뒤 삭제'라고 단정할 수 없다. 영구정지 유지 중 필요한 정보와 탈퇴 후 남길 정보를 구분해 검토해야 한다.
- 주의: 동의 철회로 인한 기능 제한은 위반 제재와 구분한다. 철회만으로 제재 기록을 새로 만들지 않는다.
- 근거 확인: 기간·항목별 필요성과 처리 근거 검토가 남아 있다. 영구정지라는 이름만으로 전체 정보를 영구 보관하지 않는다.

## 6. 영구정지 후 탈퇴자의 재가입 방지 값

- 목적: 확인된 영구정지 이용자의 제재 회피 방지.
- 현재 코드상 항목: HMAC 식별값·식별 종류, 영구정지 종류·사유·시각, 탈퇴일·만료일.
- 현재 기간: 탈퇴일부터 1년. 일반 탈퇴자 전원을 대상으로 하는 기준이 아니다.
- 최소 항목 후보: 필요한 비교용 식별값, 제재 근거·기간 관리에 필요한 최소 정보. 실명·이메일 원문·정치성향 프로필 전체를 남기는 방식으로 확대하지 않는다.
- 주의: HMAC은 비밀키로 만드는 비교용 값이다. 원문이 아니어도 이용자와 연결할 수 있으므로 익명정보라고 단정하지 않는다.
- 미결: 기존 문서상 가입·로그인 차단 연결은 미완료다. 보관 자체와 실제 방지 효과를 분리하여 확인한다.
- 근거 확인: 재가입 방지 필요성, 대체 수단, 1년의 비례성과 권리 침해 영향을 구체적으로 검토해야 한다.

## 7. 관리자 조치 이력

- 목적: 누가 어떤 근거로 조치했는지 확인하고 운영 오류·분쟁에 대응.
- 최소 항목 후보: 행위자·대상·조치·사유·시각 및 사건 연결. 공개 회원 화면에는 내부 메모나 운영자 식별정보를 노출하지 않는다.
- 현재 확정 운영 정책: DEC-020에 따라 생성일부터 1년. 기존 행은 임의로 수정·삭제하지 않고, 만료 시 통제된 경로에서 파기한다.
- 주의: 1년은 현재 제품 정책이다. 모든 커뮤니티에 법이 의무로 정한 기간이라는 뜻은 아니다. 개인정보 필드·내용별 처리 근거 검토는 별개다.

## 8. 권리침해 요청·소명·첨부

- 목적: 신청인 자격 확인, 침해 주장 검토, 조치·이의 및 분쟁 대응.
- 최소 항목 후보: 신청인 연락·자격 확인에 필요한 정보, 대상 콘텐츠, 침해 소명과 필요한 증빙, 조치·통지·처리 이력. 주민등록번호·불필요한 신분증 전체 사본을 요구하지 않는다.
- 현재 운영 기준: 정식 사건은 최종 처리일부터 5년, 정식 사건이 되지 않은 접수는 최종 처리일부터 1년. 기존 개인정보 초안과 보관정책 코드의 기준이며 운영 DB 실검증 결과는 아니다.
- 미결: 특히 5년의 필요성과 법적 근거는 기존 문서에서도 미확정이다. 다른 업종의 법정 5년 보관기간을 그대로 가져와 근거로 사용하지 않는다.
- 삭제: 근거 있는 기간이 끝나면 관련 첨부도 함께 파기하는지 실제 경로 확인이 필요하다. 증빙 속 제3자·민감정보를 최소화한다.

## 9. 사건 증거 보전 — 기존 DEC-021 유지

- 실제 소송·수사·권리침해 분쟁·정식 보전 요청 등 구체적 필요가 있어야 한다. 대상·사유·권한·기간·종료 조건과 적법한 근거를 확인한다.
- 기존 시스템은 OWNER만 설정·해제하며, 삭제 증거·신고·제재·관리자 조치 이력·권리침해 사건과 관련 자료로 대상을 제한한다.
- 전체 프로필·XP·명성·성향 데이터는 기존 보전 대상이 아니다. 운영 편의를 이유로 대상을 확대하지 않는다.
- 기존 정책상 보전 중에는 파기를 멈춘다. 해제 시 원래 만료가 남으면 그 날짜를 유지하고, 이미 지났으면 해제일부터 7일의 유예를 적용한다. 전체 보관기간을 처음부터 다시 시작하지 않는다.
- 내부 보전 버튼을 눌렀다는 사실만으로 보관의 법적 근거가 생기지 않는다. 법령상 보존 의무로 남기는 정보는 다른 정보와 분리해 저장·관리한다.

## 실행 전 우선순위

1. 철회 후 계정 유지 범위·기간·종료 방식과 영구정지 만료 기준을 결정할 자료를 정리한다. 지금 새 기간을 임의로 정하지 않는다.
2. 성향 삭제의 오류 처리와 스냅샷·복제본 등 실제 삭제 범위를 읽기 전용으로 확인한다. 이후 코드 변경·DB 실행은 별도 승인 범위다.
3. 기록별 필요성·법적 근거를 확인한다. 특히 일괄 삭제 콘텐츠 보관, 민감정보를 포함한 증거, 권리침해 5년 보관을 우선 검토한다.
4. 검토를 마친 항목만 약관·개인정보처리방침 공개 후보에 반영한다. 저장만 하고 실제 만료 파기가 안 되는지 확인하는 작업은 별도로 계획한다.
